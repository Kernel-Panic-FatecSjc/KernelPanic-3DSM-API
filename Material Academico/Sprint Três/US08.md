## US08 — Auditoria de Lançamentos

**User Story:** "Como Financeiro, quero acessar o histórico de alterações feitas em lançamentos de horas aprovadas, visualizando quem alterou, quando e o que mudou, para garantir rastreabilidade e base confiável para faturamento."

<details>
<summary>Critérios de Aceitação</summary>

- O Financeiro deve conseguir visualizar todas as alterações feitas em lançamentos aprovados.
- Cada registro deve exibir: data da alteração, quem alterou, profissional do lançamento, projeto, campo alterado, valor anterior e valor novo.
- O Financeiro deve conseguir filtrar por profissional, projeto e período.
- O histórico deve ser imutável — apenas leitura.

</details>

<details>
<summary>Cenários</summary>

**Cenário 1: Consulta de auditoria com filtros**

- Dado que sou um Financeiro e acesso o histórico de auditoria;
- Quando filtro por um profissional e um período;
- Então devo ver todas as alterações feitas nos lançamentos aprovados daquele profissional no período, com campo alterado, valor anterior e valor novo.

**Cenário 2: Lançamento sem alterações**

- Dado que um lançamento aprovado nunca foi editado após aprovação;
- Quando acesso o histórico de auditoria;
- Então esse lançamento não aparece na listagem de auditoria.

**Cenário 3: Múltiplas alterações no mesmo lançamento**

- Dado que um lançamento aprovado foi alterado mais de uma vez;
- Quando acesso o histórico de auditoria;
- Então cada alteração deve aparecer como um registro separado em ordem cronológica.

</details>

<details>
<summary>Regras de Negócio</summary>

- Apenas o Financeiro tem acesso ao histórico de auditoria.
- Apenas alterações em lançamentos aprovados geram registro de auditoria.
- O registro de auditoria é imutável — não pode ser editado ou excluído.
- O histórico registra o estado anterior e o estado posterior de cada campo alterado.

</details>

<details>
<summary>Dicionário de Dados</summary>

## Dicionário de Dados — US08

### Auditoria de Lançamentos

| Nome da variável | Descrição | Tipo de dado | Tamanho | Restrição |
| :--- | :--- | :--- | :--- | :--- |
| id | Identificador único do registro de auditoria | Integer | - | PK, Not Null |
| idLancamento | Lançamento aprovado que foi alterado | Integer | - | FK, Not Null |
| idUsuarioAlterou | Usuário que realizou a alteração | Integer | - | FK, Not Null |
| idProfissionalLancamento | Profissional dono do lançamento | Integer | - | FK, Not Null |
| idProjeto | Projeto vinculado ao lançamento | Integer | - | FK, Not Null |
| campoAlterado | Nome do campo que foi modificado | String | 255 | Not Null |
| valorAnterior | Valor do campo antes da alteração | String | 500 | Not Null |
| valorNovo | Valor do campo após a alteração | String | 500 | Not Null |
| dataAlteracao | Data e hora da alteração | Timestamp | - | Not Null |

</details>

<details>
<summary>DoR — Definition of Ready</summary>

| Critério | Descrição |
| :--- | :--- |
| **Escopo definido** | Confirmado que a auditoria registra apenas alterações em lançamentos aprovados. |
| **Campos do registro definidos** | Confirmados os campos exibidos por registro: data, quem alterou, profissional, projeto, campo, valor anterior e valor novo. |
| **Regra de imutabilidade definida** | Confirmado que registros de auditoria não podem ser editados ou excluídos. |
| **Dependência resolvida** | US3 entregue — lançamentos aprovados já existem no sistema. |

</details>

<details>
<summary>DoD — Definition of Done</summary>

| Critério | Descrição |
| :--- | :--- |
| **Registro gerado automaticamente** | Toda alteração em lançamento aprovado gera registro de auditoria sem intervenção manual. |
| **Campos exibidos corretamente** | Cada registro exibe data, quem alterou, profissional, projeto, campo alterado, valor anterior e valor novo. |
| **Filtros funcionando** | Filtros por profissional, projeto e período retornam apenas os registros correspondentes. |
| **Imutabilidade garantida** | Não é possível editar ou excluir registros de auditoria. |

</details>
