## US01 - Registro de Usuários, Projetos e Custos

**User Story:** "Como Gestor, quero cadastrar usuários com seus respectivos dados e custos por hora, cadastrar projetos com informações de identificação, responsável, equipe e prazo, e acompanhar o andamento dos projetos cadastrados, para que a empresa tenha controle sobre a estrutura das equipes e o progresso dos projetos."

<details>
<summary>Critérios de Aceitação</summary>

- O sistema deve permitir o cadastro de usuários (profissionais) com seus respectivos custos por hora (valorHora).
- O sistema deve permitir a criação de projetos associando profissionais à equipe do projeto.
- Deve ser possível associar múltiplos usuários a um único projeto.
- Todos os campos financeiros devem aceitar duas casas decimais.

</details>

<details>
<summary>Cenários</summary>

**Cenário 1: Cadastro de usuário com sucesso**

- Dado que sou um Gestor e estou na tela de cadastro de usuários;
- Quando preencho todos os campos obrigatórios e confirmo o cadastro;
- Então o sistema deve salvar o registro e exibir o usuário na listagem.

**Cenário 2: Tentativa de registro com dados incompletos**

- Dado que estou criando um projeto;
- Quando tento salvar sem preencher os campos obrigatórios;
- Então o sistema deve impedir o salvamento e destacar os campos obrigatórios em vermelho.

**Cenário 3: Acompanhamento de projetos por status**

- Dado que existem projetos cadastrados no sistema;
- Quando acesso a tela de projetos;
- Então devo visualizar os projetos organizados por status (To Do, Doing, Done).

</details>

<details>
<summary>Regras de Negócio</summary>

- Apenas o Gestor pode cadastrar usuários e criar projetos.
- Cada usuário tem um valor/hora associado no momento do cadastro.
- O valor/hora do profissional é fixo independente do projeto ao qual está alocado.
- Não é possível deletar um projeto que possui profissionais alocados.
- Cada projeto possui exatamente um Gestor responsável.
- Um projeto pode ter múltiplos profissionais alocados.
- O Profissional visualiza apenas os projetos aos quais está alocado.

</details>

<summary>Dicionário de Dados</summary>

## Dicionário de Dados — US01

### Usuário

| Nome da variável | Descrição | Tipo de dado | Tamanho | Restrição |
| :--- | :--- | :--- | :--- | :--- |
| id | Identificador único do usuário | Integer | - | PK, Not Null |
| nome | Nome completo do usuário | String | 255 | Not Null |
| email | E-mail do usuário | String | 255 | Not Null, Unique |
| senha | Senha do usuário | String | 255 | Not Null |
| cargo | Tipo de contrato do usuário | Enum | - | CLT, PJ, PJ/Hora |
| salario | Custo por hora do usuário | Decimal | (10,2) | Not Null |
| ativo | Status do usuário no sistema | Boolean | - | Not Null, Default: true |
| gestorId | Referência ao gestor responsável | Integer | - | FK, Nullable |
| dataCriacao | Data de criação do registro | Timestamp | - | Not Null |

### Projeto

| Nome da variável | Descrição | Tipo de dado | Tamanho | Restrição |
| :--- | :--- | :--- | :--- | :--- |
| id | Identificador único do projeto | Integer | - | PK, Not Null |
| nome | Nome do projeto | String | 255 | Not Null |
| descricao | Descrição composta com cliente, responsável, kick-off e equipe | String | 300 | Nullable |
| status | Estado atual do projeto | Enum | - | EM_PLANEJAMENTO, EM_ANDAMENTO, CONCLUIDO |
| prazo | Data final prevista para o projeto | Timestamp | - | Nullable |
| dataCriacao | Data de criação do registro | Timestamp | - | Not Null |

</details>

<details>
<summary>DoR — Definition of Ready</summary>

| Critério | Descrição |
| :--- | :--- |
| **Campos de usuário definidos** | Nome, email, senha, valor/hora, tipo de contrato (CLT, PJ horas fixas, PJ horas variáveis), nível de experiência (Júnior, Pleno, Sênior) e status (Ativo/Inativo) estão definidos e validados. |
| **Campos de projeto definidos** | Nome do projeto, nome do cliente, responsável pelo projeto, equipe (lista de profissionais), data de kick-off e data final estão definidos e validados. |
| **Regra de custo clara** | Definido que o valor/hora do profissional é fixo independente do projeto ao qual está alocado. |
| **Estados do projeto definidos** | Confirmados os três estados possíveis de um projeto: To Do, Doing e Done. |

</details>

<details>
<summary>DoD — Definition of Done</summary>

| Critério | Descrição |
| :--- | :--- |
| **Restrição de acesso verificada** | Profissional autenticado não acessa projetos fora da sua alocação. |
| **Valor/hora acessível para cálculo** | O valor/hora cadastrado está disponível e correto para uso nos cálculos de custo das sprints seguintes. |
| **Acompanhamento de projetos correto** | Projetos aparecem no status correto (To Do, Doing, Done) conforme o andamento real. |

</details>
