## US02 - Lançamento de Horas e Classificação de Atividades

**User Story:** "Como Profissional, quero registrar, editar e excluir apontamentos de horas com informações de projeto, atividade e período, e acompanhar meus lançamentos por status (aguardando aprovação, aprovados e rejeitados) com filtros por projeto e data, para que a empresa tenha rastreabilidade sobre o esforço da equipe e o Gestor possa validar os lançamentos."

<details>
<summary>Critérios de Aceitação</summary>

- O Profissional deve conseguir registrar um apontamento de horas informando projeto, tipo de atividade, título da sessão, horário de início e fim e data do lançamento.
- Lançamentos retroativos (data anterior ao dia atual) exigem justificativa obrigatória e entram automaticamente na fila de aprovação ao serem enviados.
- O Profissional deve conseguir editar e excluir lançamentos que ainda estão em Entrada/Saída.
- O Profissional deve conseguir acompanhar seus lançamentos organizados por status: Aguardando Aprovação, Aprovados, Rejeitados e Histórico.
- Filtros por projeto e por data devem estar disponíveis em todas as abas.

</details>

<details>
<summary>Cenários</summary>

**Cenário 1: Lançamento de horas com sucesso**

- Dado que sou um Profissional e estou na aba Entrada/Saída;
- Quando preencho todos os campos obrigatórios e salvo o lançamento;
- Então o sistema deve registrar o apontamento e exibi-lo na listagem.

**Cenário 2: Lançamento retroativo com justificativa**

- Dado que estou registrando um lançamento com data anterior ao dia atual;
- Quando tento enviar sem preencher a justificativa;
- Então o sistema deve bloquear o envio e exibir mensagem de campo obrigatório.

**Cenário 3: Envio para aprovação**

- Dado que tenho um lançamento salvo na aba Entrada/Saída;
- Quando clico em enviar;
- Então o lançamento deve mover para Aguardando Aprovação e não pode mais ser editado ou excluído.

**Cenário 4: Visualização de lançamento rejeitado**

- Dado que o Gestor reprovou um lançamento com motivo;
- Quando acesso a aba Rejeitados;
- Então devo visualizar o lançamento com o motivo da reprovação informado pelo Gestor.

</details>

<details>
<summary>Regras de Negócio</summary>

**Fluxo de estado:**

- Lançamento criado → fica em Entrada/Saída (não enviado)
- Lançamento enviado → AGUARDANDO_APROVACAO
- Lançamento com data anterior ao dia atual → AGUARDANDO_APROVACAO + justificativa obrigatória
- Gestor aprova → APROVADO
- Gestor rejeita → REJEITADO + motivo_rejeicao obrigatório

**Regras de validação:**

- Lançamentos em Entrada/Saída podem ser editados e excluídos.
- Lançamentos enviados não podem ser editados ou excluídos.
- Se data_lancamento < hoje, justificativa é obrigatória.
- O total de horas é calculado automaticamente a partir do horário de início e fim.

**Atores:**

- Profissional — CRUD na página de Entrada/Saída.
- Gestor — aprova ou rejeita lançamentos com status AGUARDANDO_APROVACAO.

</details>

<summary>Dicionário de Dados</summary>

## Dicionário de Dados — US02

### Apontamento de Horas

| Nome da variável | Descrição | Tipo de dado | Tamanho | Restrição |
| :--- | :--- | :--- | :--- | :--- |
| id | Identificador único do apontamento | Integer | - | PK, Not Null |
| usuarioId | Usuário que realizou o apontamento | Integer | - | FK, Not Null |
| tarefaId | Tarefa vinculada ao apontamento | Integer | - | FK, Nullable |
| tituloSessao | Título do apontamento | String | 255 | Not Null |
| descricao | Descrição detalhada da atividade | String | 1000 | Nullable |
| tipoAtividade | Tipo da atividade realizada | Enum | - | ANALISE, DESENVOLVIMENTO, TESTES, CORRECAO_BUG, FEATURE |
| dataLancamento | Data do apontamento | Date | - | Not Null |
| inicio | Hora de início da atividade | Time | - | Not Null |
| fim | Hora de fim da atividade | Time | - | Not Null |
| justificativa | Justificativa para lançamento retroativo | String | 1000 | Not Null quando dataLancamento < data atual |
| motivoRejeicao | Motivo informado pelo Gestor ao rejeitar | String | 500 | Not Null quando estado = REJEITADO |
| estado | Estado atual do apontamento | Enum | - | PENDENTE, AGUARDANDO_APROVACAO, APROVADO, REJEITADO |
| dataCriacao | Data de criação do registro | Timestamp | - | Not Null |

</details>

<details>
<summary>DoR — Definition of Ready</summary>

| Critério | Descrição |
| :--- | :--- |
| **Tipos de atividade definidos** | Análise, Desenvolvimento, Testes, Correção de Bug e Feature confirmados para seleção no apontamento. |
| **Fluxo de status definido** | Definido que lançamento criado vai para aprovação, podendo ser aprovado ou rejeitado com motivo obrigatório. |
| **Regra de lançamento retroativo definida** | Definido que lançamento com data anterior ao dia atual exige justificativa obrigatória e entra automaticamente na fila de aprovação. |
| **Campos do apontamento definidos** | Projeto, título da sessão, descrição, responsável, tipo de atividade, horário de início, horário de fim, data de lançamento e justificativa quando retroativo. |

</details>

<details>
<summary>DoD — Definition of Done</summary>

| Critério | Descrição |
| :--- | :--- |
| **Cálculo de horas correto** | Total por registro calculado corretamente a partir do horário de início e fim. Total da semana recalcula conforme filtros aplicados. |
| **Regra retroativa aplicada** | Lançamento com data anterior ao dia atual não é enviado sem justificativa preenchida. |
| **Fluxo de status verificado** | Lançamento enviado aparece em Aguardando Aprovação. Aprovado aparece em Aprovados. Rejeitado aparece em Rejeitados com motivo visível. |
| **Filtros corretos em todas as abas** | Filtro por projeto e por data funcionam corretamente em todas as páginas, com totais recalculados após aplicação. |

</details>
