## US02 - Gestão de Tarefas

**User Story:** "Como Gestor, quero criar e gerenciar tarefas dentro de cada projeto, podendo atribuí-las a profissionais alocados e acompanhar seu status, para que o time saiba exatamente o que precisa ser feito e eu tenha visibilidade do andamento."

<details>
<summary>Critérios de Aceitação</summary>

- O sistema deve permitir ao Gestor criar tarefas vinculadas a um projeto existente.
- Cada tarefa deve poder ser atribuída a um profissional alocado no projeto.
- O Gestor deve conseguir alterar o status de uma tarefa (to do, doing, done).
- O Profissional deve visualizar apenas as tarefas atribuídas a ele.
- Não deve ser possível atribuir uma tarefa a um profissional não alocado no projeto.
- Tarefas podem ser editadas pelo Gestor após criação.

</details>

<details>
<summary>Cenários</summary>

**Cenário 1: Criação de tarefa com sucesso**

- Dado que sou um Gestor e estou na tela de tarefas de um projeto;
- Quando crio uma tarefa informando nome, descrição e atribuindo a um profissional alocado;
- Então a tarefa deve aparecer na lista com status to do e visível para o profissional responsável.

**Cenário 2: Tentativa de atribuição a profissional não alocado**

- Dado que estou criando uma tarefa em um projeto;
- Quando tento atribuí-la a um profissional que não está alocado nesse projeto;
- Então o sistema deve impedir a atribuição e exibir mensagem de erro.

**Cenário 3: Atualização de status de tarefa**

- Dado que existe uma tarefa com status to do;
- Quando o Gestor altera o status para doing ou done;
- Então a tarefa deve refletir o novo status na listagem do projeto.

</details>

<details>
<summary>Regras de Negócio</summary>

- Apenas o Gestor pode criar, editar e atribuir tarefas.
- Uma tarefa deve estar obrigatoriamente vinculada a um projeto.
- Apenas profissionais alocados no projeto podem ser atribuídos a uma tarefa.
- O Profissional visualiza apenas as tarefas atribuídas a ele.
- Tarefas podem ser editadas mas não deletadas — apenas desativadas.
- O status inicial de toda tarefa criada é to do.

</details>

<details>
<summary>Dicionário de Dados</summary>

## Dicionário de Dados — US02

### Tarefa

| Nome da variável | Descrição | Tipo de dado | Tamanho | Restrição |
| :--- | :--- | :--- | :--- | :--- |
| id | Identificador único da tarefa | Integer | - | PK, Not Null |
| nome | Nome da tarefa | String | 255 | Not Null |
| descricao | Descrição detalhada da tarefa | String | 1000 | Nullable |
| idProjeto | Projeto ao qual a tarefa pertence | Integer | - | FK, Not Null |
| idResponsavel | Profissional atribuído à tarefa | Integer | - | FK, Not Null |
| status | Status atual da tarefa | Enum | - | TO_DO, DOING, DONE, BLOQUEADA |
| dataCriacao | Data de criação da tarefa | Timestamp | - | Not Null |

</details>

<details>
<summary>DoR — Definition of Ready</summary>

| Critério | Descrição |
| :--- | :--- |
| **Campos da tarefa definidos** | Nome, descrição, projeto vinculado, profissional responsável e status definidos e validados. |
| **Status possíveis definidos** | Confirmados os três status de tarefa: to do, doing e done. Bloqueada tratada na US5. |
| **Regra de atribuição clara** | Definido que apenas profissionais alocados no projeto podem ser atribuídos a uma tarefa. |
| **Dependência resolvida** | US1 entregue — profissionais e projetos já estão cadastrados no sistema. |

</details>

<details>
<summary>DoD — Definition of Done</summary>

| Critério | Descrição |
| :--- | :--- |
| **Restrição de atribuição verificada** | Não é possível atribuir tarefa a profissional fora do projeto. |
| **Visibilidade do profissional correta** | Profissional visualiza apenas as tarefas atribuídas a ele. |
| **Status refletindo o andamento** | Alterações de status feitas pelo Gestor aparecem corretamente na listagem. |

</details>
