## US03 - Aprovação de Horas

**User Story:** "Como Gestor, quero acessar um painel de aprovação de horas lançadas pelos profissionais, podendo filtrar por profissional, projeto ou período, aprovar ou reprovar lançamentos individualmente ou em lote, e ao reprovar informar obrigatoriamente o motivo, para que apenas horas aprovadas sejam contabilizadas no custo real do projeto."

<details>
<summary>Critérios de Aceitação</summary>

- O sistema deve exibir ao Gestor todos os lançamentos aguardando aprovação.
- O Gestor deve conseguir filtrar lançamentos por profissional, projeto e período.
- O Gestor deve conseguir aprovar ou reprovar lançamentos individualmente ou em lote.
- Ao reprovar, o motivo deve ser obrigatório.
- Apenas lançamentos aprovados devem ser contabilizados no custo real do projeto.
- O Profissional deve visualizar o motivo da reprovação no seu painel.

</details>

<details>
<summary>Cenários</summary>

**Cenário 1: Aprovação individual com sucesso**

- Dado que sou um Gestor e estou no painel de aprovação;
- Quando aprovo um lançamento individualmente;
- Então o lançamento deve mudar para status aprovado e ser contabilizado no custo do projeto.

**Cenário 2: Reprovação sem motivo**

- Dado que estou reprovando um lançamento;
- Quando tento confirmar a reprovação sem informar o motivo;
- Então o sistema deve bloquear a ação e exibir mensagem de campo obrigatório.

**Cenário 3: Aprovação em lote**

- Dado que existem múltiplos lançamentos aguardando aprovação;
- Quando seleciono mais de um e confirmo a aprovação em lote;
- Então todos os selecionados devem mudar para status aprovado simultaneamente.

**Cenário 4: Filtro por projeto e período**

- Dado que estou no painel de aprovação;
- Quando filtro por um projeto específico e um período;
- Então apenas os lançamentos daquele projeto e período devem ser exibidos.

</details>

<details>
<summary>Regras de Negócio</summary>

- Apenas o Gestor pode aprovar ou reprovar lançamentos.
- Motivo de reprovação é obrigatório — reprovação sem motivo não é permitida.
- Apenas lançamentos aprovados são contabilizados no custo real do projeto.
- Lançamentos reprovados retornam ao Profissional com o motivo visível.
- Um lançamento aprovado não pode ser revertido para aguardando aprovação.
- Lançamentos retroativos seguem o mesmo fluxo de aprovação.

</details>

<details>
<summary>Dicionário de Dados</summary>

| Nome da variável | Descrição | Tipo de dado | Tamanho | Restrição |
| :--- | :--- | :--- | :--- | :--- |
| id_lancamento | Identificador único do lançamento | UUID | - | PK, Not Null |
| id_gestor | Gestor que realizou a ação | UUID | - | FK, Not Null |
| status_aprovacao | Status do lançamento | Enum | - | aguardando, aprovado, reprovado |
| motivo_reprovacao | Motivo informado pelo Gestor ao reprovar | String | 500 | Not Null quando reprovado |
| data_aprovacao | Data da ação de aprovação ou reprovação | Timestamp | - | Not Null |

</details>

<details>
<summary>DoR — Definition of Ready</summary>

| Critério | Descrição |
| :--- | :--- |
| **Fluxo de aprovação definido** | Confirmado que lançamentos aprovados são contabilizados e reprovados retornam ao profissional com motivo. |
| **Regra de motivo obrigatório definida** | Definido que reprovação sem motivo preenchido não é permitida. |
| **Dependência resolvida** | US4 entregue — lançamentos de horas já existem no sistema para serem aprovados. |
| **Filtros definidos** | Confirmados os filtros disponíveis no painel: profissional, projeto e período. |

</details>

<details>
<summary>DoD — Definition of Done</summary>

| Critério | Descrição |
| :--- | :--- |
| **Regra de motivo obrigatório verificada** | Não é possível reprovar um lançamento sem informar o motivo. |
| **Contabilização correta** | Apenas lançamentos com status aprovado são somados ao custo real do projeto. |
| **Motivo visível ao profissional** | Profissional visualiza o motivo da reprovação no seu painel de rejeitados. |
| **Filtros funcionando** | Filtros por profissional, projeto e período retornam apenas os lançamentos correspondentes. |

</details>
