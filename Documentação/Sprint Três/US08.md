## US08 - Auditoria de Lançamentos

**User Story:** "Como Administrador, quero acessar o histórico de alterações feitas em lançamentos de horas, visualizando quem alterou, quando e o que mudou, para garantir rastreabilidade e auditoria dos dados."

<details>
<summary>Critérios de Aceitação</summary>

- O Administrador deve conseguir visualizar todas as alterações feitas em lançamentos de horas.
- Cada registro de auditoria deve exibir quem alterou, quando alterou e o que mudou (valor anterior e valor novo).
- O Administrador deve conseguir filtrar o histórico por profissional, projeto e período.
- O histórico de auditoria deve ser imutável.

</details>

<details>
<summary>Cenários</summary>

**Cenário 1: Consulta de auditoria de lançamento**

- Dado que sou um Administrador e acesso o histórico de auditoria;
- Quando filtro por um profissional e um período;
- Então devo ver todas as alterações feitas nos lançamentos daquele profissional no período, com valor anterior e valor novo.

**Cenário 2: Lançamento sem alterações**

- Dado que um lançamento nunca foi editado após criação;
- Quando acesso o histórico de auditoria desse lançamento;
- Então o sistema deve exibir apenas o registro de criação original.

</details>

<details>
<summary>Regras de Negócio</summary>

- Apenas o Administrador tem acesso ao histórico de auditoria.
- Toda alteração em um lançamento gera automaticamente um registro de auditoria.
- O registro de auditoria é imutável — não pode ser editado ou excluído.
- O histórico registra o estado anterior e o estado posterior de cada campo alterado.

</details>

<details>
<summary>Dicionário de Dados</summary>

| Nome da variável | Descrição | Tipo de dado | Tamanho | Restrição |
| :--- | :--- | :--- | :--- | :--- |
| id_auditoria | Identificador único do registro de auditoria | UUID | - | PK, Not Null |
| id_lancamento | Lançamento que foi alterado | UUID | - | FK, Not Null |
| id_usuario | Usuário que realizou a alteração | UUID | - | FK, Not Null |
| campo_alterado | Nome do campo que foi modificado | String | 255 | Not Null |
| valor_anterior | Valor do campo antes da alteração | String | 500 | Not Null |
| valor_novo | Valor do campo após a alteração | String | 500 | Not Null |
| data_alteracao | Data e hora da alteração | Timestamp | - | Not Null |

</details>

<details>
<summary>DoR — Definition of Ready</summary>

| Critério | Descrição |
| :--- | :--- |
| **Campos auditados definidos** | Confirmado quais campos do lançamento geram registro de auditoria quando alterados. |
| **Regra de imutabilidade definida** | Confirmado que registros de auditoria não podem ser editados ou excluídos. |
| **Dependência resolvida** | US4 entregue — lançamentos de horas já existem no sistema para serem auditados. |

</details>

<details>
<summary>DoD — Definition of Done</summary>

| Critério | Descrição |
| :--- | :--- |
| **Registro gerado automaticamente** | Toda alteração em lançamento gera registro de auditoria sem intervenção manual. |
| **Valor anterior e novo corretos** | O registro exibe corretamente o estado antes e depois da alteração. |
| **Filtros funcionando** | Filtros por profissional, projeto e período retornam apenas os registros correspondentes. |

</details>
